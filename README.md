# Career Sarthii

A local, bilingual exam preparation website built from the supplied prototype. It includes signup/login, practice history, interview session summaries, chat history, study document storage, and optional Gemini powered tutoring and mock-paper generation. Application data is stored in MongoDB Atlas.

## Run on Windows

1. Create a MongoDB Atlas cluster and database user; add your computer's IP address to the project's IP access list, then copy the application connection URI. Atlas requires a database user and an allowed client IP. URL-encode special characters in the database user's password before putting it in the URI.
2. Install Node.js 22.13 or newer and open PowerShell in this folder.
3. Copy `.env.example` to `.env`, then paste your MongoDB connection URI into `MONGODB_URI`. Set `GEMINI_API_KEY` too if you want AI features.
4. Run `npm install`, then `npm start`, and open <http://localhost:3000>.

MongoDB collections are created automatically in the database named by `MONGODB_DB` (default `career_sarthii`). The app creates its indexes at startup. Account data, attempts, chats, interviews, and uploaded papers remain in your Atlas database. Secrets stay in `.env` and are never sent to the browser.

### Set the Gemini key

Add the key to `.env` as `GEMINI_API_KEY=your-key`.

When no Gemini key is configured, AI chat explains that Gemini is unavailable and mock-paper generation uses a small included practice set. The original question bank is only sample content; real previous-year papers should be uploaded from the Study documents section. Uploaded PDFs and text notes can be used as context for AI chat.

## Data and privacy

- Passwords are stored as scrypt hashes; login uses an HttpOnly session cookie.
- Account records and uploaded files are stored in your MongoDB database.
- Uploaded PDF, TXT, and DOCX files are limited to 8 MB each. Gemini chat currently reads PDF and TXT study documents as context.
- A configured Gemini key sends the chat message and up to three recent PDF/TXT documents to Google's Gemini API for that response. Consult Google's current terms before using real personal or copyrighted material.
- Exam alerts link to official sites; they are not automatically monitored or sent as notifications.

## Important limits

This is a runnable local application, not a production deployment. The seeded question data is illustrative and does not claim to be authentic past exam papers. Before public hosting, add HTTPS, rate limits, email verification/password reset, account export, backups, and a deployment-specific secret manager.

## Deploy on Render

1. Push this folder to GitHub (the folder containing `package.json` must be the repo root, or set Root Directory).
2. Render: New + > Web Service > pick repo. Build Command `npm install`, Start Command `npm start`.
3. Environment: `MONGODB_URI`, `JWT_SECRET` (any long random string), `GEMINI_API_KEY`.
4. MongoDB Atlas > Network Access > add `0.0.0.0/0` so Render can connect.

## Questions (no AI needed)

- `data/bank.js` is the hand-written bank (GK, science, English, analogy, syllogism). Add rows in the same format.
- Maths and reasoning practice (percentage, time and work, profit and loss, ratio, simplification, series, coding) is generated by rules in `questions.js`, so answers are always exact and instant.
- Real previous year papers: put JSON files in `data/pyq/` as an array of
  `{"exam":"ssc-cgl","year":2023,"s":"quant","c":"pct","q":"...","o":["a","b","c","d"],"a":1,"x":"explanation"}`.
  `exam` must match an exam id from `js/data.js`. Years then appear in the PYQ tab automatically after a restart.
- AI (Gemini) is used only for chat, interview feedback and the optional "Extra paper with AI". Chat streams the reply as it is written. Thinking level is `low` by default (`GEMINI_THINKING=low|medium|high`).

## Chat speed settings (optional environment variables)

- `GEMINI_CHAT_MODEL` default `gemini-3.5-flash-lite` (fastest). If it sends nothing within 8 seconds (`GEMINI_FIRST_TOKEN_MS`) or is busy, the chat automatically tries `gemini-3.6-flash`, then `GEMINI_MODEL` and `GEMINI_FALLBACK_MODELS`.
- `GEMINI_THINKING` leave empty (minimal for flash-lite, low for others).

## Previous year papers (PYQ), uploaded by students and shared

- A student picks the exam year. If the paper is not in the database, they upload the official PDF (and the answer key PDF if separate). Gemini reads it, splits it by subject and saves the MCQs with answers and explanations in MongoDB (`pyq`). From then on every student preparing for that exam gets it directly, no upload needed.
- Limits: 5 uploads per user per day, a saved paper cannot be overwritten by users, and the AI rejects a PDF that is not the paper for that exam and year.
- Answers solved by AI (no key supplied) are marked in the quiz. Set `ADMIN_EMAIL` (your login email) in Render so you can delete a bad paper from the subject screen.
- Profile page: name, gender, category, qualification, exam, bio and photo. Changing qualification unlocks the exams for that level.

## Papers with shifts, reports and admin

- A year can hold several papers or shifts ("Paper 1", "Paper 2", "Shift 1" ...). Each one is uploaded separately and practised separately.
- Students can press the star at the bottom right of a paper to report a problem. The admin page (sidebar, visible only to the account whose email is in `ADMIN_EMAIL`) shows reported papers first with a star, lets you review every question and answer, and then Keep (dismiss the reports) or Delete the paper.

## Admin login

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` (8+ characters) in Render. On every start the server creates that account (or resets its password to the value you set). Log in on the normal login page with them and you land on the Admin page.

## Hindi / English questions

When the site is in Hindi, questions that only exist in English are translated by Gemini (with retries on other models when busy) and cached in MongoDB (`translations`), so every later student gets them instantly. English language and Hindi language subject questions are never translated. Papers that exist only in Hindi are translated into English when they are imported.
Translations are also prepared in advance: right after a paper is imported and when the server starts (question bank and every saved paper), so students rarely wait.
